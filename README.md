# Expire X

Expiry tracker (food, medicine, cosmetics, documents, warranty, subscription, other) with
OCR + AI-assisted entry and daily email reminders. Next.js 15 (App Router) · Supabase ·
Gemini (multimodal OCR) · Resend. Dark, glassmorphic, mobile-first.

## Architecture (where logic runs)
- **Item CRUD / dashboard / search** — client & server components query Supabase directly, so
  RLS (`auth.jwt()->>'sub'`, the Clerk user id) is enforced on every read/write.
- **`/api/scan`** (Next.js Route Handler, Node runtime) — Gemini reads the photo and returns
  structured JSON (Tesseract.js offline fallback). Returns extraction only; **never writes**.
  The Add-Item form is the mandatory confirmation; nothing is saved until the user presses **Save**.
- **`reminders`** (Supabase Edge Function, service-role) — invoked daily by `pg_cron`; sends
  Resend emails at 30/15/7/3/1 days, deduped via `notification_log`, logging only after a
  confirmed send.

## Prisma ↔ RLS (manual sync — important)
Prisma owns **tables/columns only** (`prisma/schema.prisma`). RLS policies, the
`auth.users → public.users` trigger, the storage bucket/policies, and the cron job live in
`supabase/migrations/*.sql` and are **not** generated by Prisma. After any schema change you
must update BOTH and re-apply the SQL. Prisma is never used at runtime (that would bypass RLS).

## Setup

### 0. Prerequisites
Node 20+, a Supabase project, a Google Cloud project, a Resend account, (optional) Vercel.

### 1. Install & env
```bash
npm install
cp .env.example .env.local   # then fill in values (see table below)
```

### 2. Supabase: schema + policies
1. Create a project. From **Project Settings → API**: copy `NEXT_PUBLIC_SUPABASE_URL`,
   `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
2. From **Project Settings → Database**: copy the connection string into `DATABASE_URL` and
   `DIRECT_URL` (use the direct `:5432` connection for migrations).
3. Create tables/enums:
   ```bash
   npx prisma migrate dev --name init
   ```
4. In the **SQL Editor**, run `supabase/migrations/0001_rls_and_storage.sql`
   (RLS policies, updated_at trigger, private `item-images` bucket + policies).

### 3. Auth (Clerk — native third-party auth)
Auth is handled by **Clerk**, not Supabase Auth. Supabase only trusts Clerk's session token
so RLS (`auth.jwt()->>'sub'`) runs as the Clerk user. Two-sided setup:
- **Clerk dashboard**: enable the Supabase integration (adds the `role: "authenticated"` claim
  to session tokens). Copy `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` + `CLERK_SECRET_KEY` into env.
- **Supabase → Authentication → Sign In / Up → Third-Party Auth → Add Clerk**: enter your
  Clerk domain (e.g. `your-instance.clerk.accounts.dev`). Without this, all data requests are
  treated as anonymous and RLS returns nothing.
- App routes: `/login` (`<SignIn>`) and `/sign-up` (`<SignUp>`); `public.users` is upserted
  from Clerk on first authenticated load.

### 4. Verify RLS isolation (gate before using the app)
Simulate two Clerk users in the SQL editor (set `request.jwt.claims` with a string `sub`) and
confirm each sees only their own rows — see `supabase/tests/rls_isolation_test.sql`.

### 5. Gemini (OCR + extraction)
Get a free API key from **Google AI Studio** → `GEMINI_API_KEY`. Gemini reads the label photo
**and** extracts `product_name` / `expiry_date` / `category` in one multimodal call — no Cloud
Vision and no GCP billing. **Tesseract.js** is the offline fallback if the Gemini image call fails.

### 7. Resend (email)
1. Create an API key → `RESEND_API_KEY`.
2. Verify a sending domain (or use `onboarding@resend.dev` for testing) → set
   `RESEND_FROM`, e.g. `Expire X <reminders@yourdomain.com>`.

### 8. Reminder Edge Function + cron
```bash
supabase login
supabase link --project-ref <PROJECT_REF>
# custom x-cron-secret auth, so skip JWT verification:
supabase functions deploy reminders --no-verify-jwt
supabase secrets set RESEND_API_KEY=re_... RESEND_FROM="Expire X <reminders@yourdomain.com>" CRON_SECRET=<long-random>
```
`SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are injected into functions automatically.

Enable extensions (**Database → Extensions**): `pg_cron`, `pg_net`. Edit
`supabase/migrations/0002_cron.sql` — replace `<PROJECT_REF>` and `<CRON_SECRET>` — and run it
in the SQL Editor. It schedules `30 2 * * *` UTC = **08:00 Asia/Kolkata**.

Smoke-test without waiting a day:
```bash
# seed an item with expiry_date = today+7, then:
curl -X POST https://<PROJECT_REF>.functions.supabase.co/reminders \
  -H "x-cron-secret: <CRON_SECRET>"
# expect JSON { sent: 1, ... }; running again sends 0 (dedup).
```

### 9. Run / deploy
```bash
npm run dev      # http://localhost:3000
npm run build
```
Deploy to **Vercel**: add every `NEXT_PUBLIC_*`, `SUPABASE_SERVICE_ROLE_KEY`,
`GOOGLE_VISION_CREDENTIALS_B64`, and `GEMINI_API_KEY` env var in the project settings.
(`RESEND_*` and `CRON_SECRET` live only in Supabase function secrets, not Vercel.)

## Environment variables
| Var | Where | Purpose |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Vercel + local | Supabase project URL (client-safe) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Vercel + local | Anon/publishable key (client-safe) |
| `SUPABASE_SERVICE_ROLE_KEY` | Vercel + local (server only) | Privileged key; never in client bundles |
| `DATABASE_URL` | local only | Prisma migrations |
| `DIRECT_URL` | local only | Prisma migrations (direct conn) |
| `GEMINI_API_KEY` | Vercel + local (server only) | Gemini OCR + extraction (multimodal) |
| `RESEND_API_KEY` | Supabase function secret | Reminder emails |
| `RESEND_FROM` | Supabase function secret | Verified sender |
| `CRON_SECRET` | Supabase function secret + `0002_cron.sql` | Shared secret guarding the function |

## Scope (v1)
In: 7 categories, auth, CRUD, dashboard, search/filter, OCR+AI confirm-before-save, email
reminders. Out: vector DB, push notifications, family sharing, computed expiry from
manufacture date (stored but informational only).
